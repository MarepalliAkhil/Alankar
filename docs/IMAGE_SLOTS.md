# Image slots

Generated by `npm run photos:inventory`. Drop `<slot>.webp|jpg|jpeg|png` into `frontend/public/photos/` (Meera: `frontend/public/photos/meera/`), then run `npm run photos:optimize` (originals go to `photos-originals/`, WebP at 640, 1080, 1600 and 2400 px wide (never larger than the original), quality 78, a tiny placeholder, contrast stats) and restart `npm run dev`. A slot with no photo shows a plain themed gradient with the glass on top; nothing is drawn. The admin content editor can set the first home picture by URL.

## Which picture each page uses

| Page | Full-window background | Framed header |
|---|---|---|
| Home (/) | scrolling: Alankar reception, Salon, Spa, Parlor (one per section, crossfade) | none |
| /salon | salon-background | salon-hero (a different picture) |
| /spa | spa-background | spa-hero |
| /beauty-parlor | parlor-background | parlor-hero |
| Booking (/customer/book) | the division being booked (salon, spa, parlor), crossfading with the theme tint; "All" = shop-background | that division's hero (a different picture), or a close crop of shop-background for All |
| Every other page: customer dashboard, bookings list, Zen Chat, wallet, packages, memberships, gift cards, shop, orders, invoices, profile; all receptionist, stylist and admin pages; login, register; For Zenotians | shop-background (Alankar reception) | none |

Every background sits under a soft veil (about 82 to 86 percent of the page colour, checked for AA against the real photos), is sharp (no blur filter; only data-heavy staff pages may use up to 4 px) and is decorative (empty alt). The placeholder is removed as soon as the sharp picture has loaded.

**Portrait phones.** Optional extra slots shop-background-mobile, salon-background-mobile, spa-background-mobile, parlor-background-mobile (ideal 1080x1920, better 1290x2796). On a portrait screen of 900 px or less ((orientation: portrait) and (max-width: 900px), by screen shape, never by device name) the mobile photo is used when it exists; if it does not, the landscape photo is shown in a short band (cover scale at most 1.25). Only one of the two is ever downloaded. See docs/IMAGE_QUALITY.md for the sizes each slot needs.

## AIR, the virtual receptionist (owner-supplied character pictures)

Square WebP (or PNG) pictures, **1024x1024**, in `frontend/public/photos/air/`, named exactly as below. `npm run photos:optimize` keeps each whole and square (never stretched) as WebP at 1024 px plus a 512 px copy (`<slot>-512.webp`), keeps transparency, and keeps the original in `frontend/photos-originals/air/`. A picture **without** transparency has its plain white surround made transparent (only near-white pixels connected to the edge, so white gloves and highlights stay). Until the optimizer has run, a picture with a plain background is shown inside a round frame. A pose without its own file shows `air.webp`; when that is missing too, the idle picture is used. The first pose is preloaded when the popup is about to open.
